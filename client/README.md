# Codex SSH Bridge

在 VS Code Remote-SSH 中使用本地 Codex 登录和网络处理远程代码。插件分为本地对话面板和远程助手，复用 VS Code 已建立的连接。远程主机无需安装 Codex 或为模型请求配置代理。

## 安装与使用

1. 在本机安装 Codex CLI，并在本地终端执行 `codex login`。已经登录的本地 CLI 会复用原登录状态。
2. 在 VS Code 中使用“扩展：从 VSIX 安装”安装 `dist/codex-ssh-bridge-1.1.0.vsix`。该插件在本地运行。更新已有安装后，执行“开发人员：重新加载窗口”以载入新代码。
3. 用 Remote-SSH 打开远程项目文件夹。在活动栏打开 Codex SSH，在顶部设置菜单点击“安装远程助手”，将随包提供的助手安装到当前 SSH 主机。若 VS Code 要求重新加载窗口，重新加载后继续。
4. 在顶部设置菜单点击“连接”，检查本地登录和远程主机状态。输入任务并发送。可以附加远程编辑器中选中的代码。

远程助手也单独提供为 `dist/codex-ssh-bridge-remote-1.1.0.vsix`，应安装到 SSH 主机而非只安装在本地。两个包版本应一致。已有官方 Codex 扩展可以继续保留，本插件使用独立的面板和对话。

## 操作方式

读取、列目录和文本搜索直接返回远程结果。默认使用“逐次批准”：修改文件前展示差异并要求确认，执行命令前单独确认。权限还可设为“只读”或“完全访问”；只读禁止修改文件和执行命令，完全访问经确认启用后允许本对话免逐次确认。文件读取后的 SHA-256 必须匹配，所有权限模式都拒绝覆盖新修改或未保存的编辑。单个文件限制为 1 MiB UTF-8 文本，新建文件不会覆盖已有文件。

远程 shell 命令从选定工作区目录启动，以远程登录用户身份执行，不受文件工具的目录边界约束。默认超时 120 秒，上限 300 秒，输出上限约 64 KiB；停止任务会取消远程助手跟踪的命令进程组。停止不会撤销已经应用的文件修改或已经发生的命令副作用。

输入区左侧的“＋”保留附加选中代码功能，旁边选择远程操作权限；右侧选择模型和该模型支持的推理强度，再依次显示麦克风占位与发送按钮。麦克风尚未实现录音，任务运行时发送按钮切换为停止。

默认模型取自当前账户实际可用模型列表，推理选项也来自模型列表。模型、推理强度和权限只对当前远程对话生效，随对话保存，从下一条消息生效；切换设置不会清空聊天或修改全局 Codex 配置。顶部左侧显示项目名称，右侧依次为历史、设置和新对话。项目菜单支持创建带自定义名称的项目、打开远程目录，以及“不选择项目”；未选择项目的对话按 SSH 主机归入“未归类”。已注册项目按当前窗口的 SSH 主机和目录自动匹配，选择其他目录的项目会打开新的 Remote-SSH 窗口。设置菜单提供连接状态、连接、远程助手安装和本地登录，“安装更新”暂为禁用占位。历史列表汇总当前远程的所有项目及未归类对话，支持搜索、点击继续聊天、悬浮或键盘聚焦后在 Codex 中打开、删除。删除会归档原生对话并将本地快照移至 `trash/`，保留恢复能力；跨目录继续聊天时会打开匹配的 SSH 窗口并恢复选定对话。用户的本地 Codex 登录仍由 Codex 自行保存和刷新。

## 本地项目与记录

连接后通过本地 Codex 的项目接口注册 `[SSH] <SSH 主机> <项目名称>`（默认使用目录名）；未归类对话注册到该 SSH 主机的独立记录分组，并为新对话设置项目归属。主机连接标识和远程路径共同决定项目身份，不同机器上的同名目录会分别保存。

本地记录目录为 `$CODEX_HOME/ssh-projects/`，未设置 `CODEX_HOME` 时使用 `~/.codex/ssh-projects/`。每个项目的 `project.json` 保存远程映射，`sessions/` 保存对话快照，`operations.jsonl` 追加记录通过插件执行的文件操作、命令、结果和失败信息。面板显示最近 100 条消息，完整会话保留在 Codex 原生历史中。修改文件内容和命令输出也会进入本地记录。

“在 Codex 中打开”使用桌面应用的工作区链接。若桌面项目列表尚未刷新，在桌面应用中添加面板提示的本地记录目录，即可将该目录作为工作区打开。之后重新连接插件，会复用该目录对应的桌面项目并归入已有 SSH 聊天。桌面应用当前是否自动展示通过外部 App Server 新增的项目，仍取决于其项目列表同步行为。远程代码保留在 SSH 主机上，不会下载为本地副本；继续执行远程操作需要匹配的 VS Code SSH 窗口提供桥接工具。

## 配置与诊断

唯一配置项为 `codexSSH.codexPath`，默认 `codex`，表示本地 Codex 可执行文件。macOS 还会搜索常用 Homebrew 路径。需要设置时，在本地用户设置中指定路径，不填远程路径。

命令面板提供“Codex SSH: 诊断连接（远程临时目录）”。该命令在远程临时目录检查新建、读取、修改、搜索和命令执行，然后清理该临时目录；同时检查本地 Codex 握手与登录状态，不运行模型任务。结果写入本地插件存储目录的 `diagnostics.json`，并在编辑器打开。普通输出见“Codex SSH Bridge”输出通道。

## 开发与验证

运行 `npm test` 执行文件边界、编辑冲突、命令取消、审批和 JSON-RPC 测试。运行 `npm run package` 生成两个 VSIX，主包内包含远程助手。运行 `node scripts/smoke-model.js` 可执行一次最小模型与工具往返测试，只提供固定测试文件名，会使用账户的模型额度。运行 `node scripts/smoke-codex.js` 检查真实本地 Codex 握手、登录状态及动态工具注册；该检查不消耗模型生成请求。

运行时没有 npm 依赖，远程助手只使用 VS Code Server 自带的 Node.js。打包仅使用 Python 3 标准库。已适配的本地协议版本为 Codex CLI 0.154.0，较旧版本可能不支持本插件使用的动态工具接口。

本地 Codex 使用 stdio JSON-RPC，不监听公网端口。内置 shell 工具关闭，本地线程使用只读沙箱；项目操作通过六个远程工具完成。没有把本地线程的系统权限视为远程命令的沙箱，远程写入和命令确认由远程助手执行。

接口依据：[Codex App Server](https://learn.chatgpt.com/docs/app-server)、[本地登录缓存](https://learn.chatgpt.com/docs/auth#login-caching)、[VS Code 本地与远程扩展通信](https://code.visualstudio.com/api/advanced-topics/remote-extensions#communicating-between-extensions-using-commands)。动态工具是实验性接口，需要随 Codex 版本继续验证。已在 macOS 本地 Codex CLI 0.154.0 与 Ubuntu 22.04 ARM64 Remote-SSH 会话验证本地认证、模型与工具往返，以及远程临时目录的读写、搜索和命令执行。Windows 和 Linux 本地客户端尚未实机验证。此项目提供源码与本地安装包，没有发布到扩展市场。
